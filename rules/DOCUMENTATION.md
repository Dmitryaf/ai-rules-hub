# Документация и знания проекта

## Типы документов

Не смешивать разные сроки жизни:

| Документ | Содержит | Не содержит |
| --- | --- | --- |
| Product | назначение, пользователи, ценность, границы | текущие задачи и журнал команд |
| Project rules | обязательные локальные ограничения | временные догадки |
| Architecture | фактические границы, целевое направление, компромиссы | неподтверждённые будущие модули как факт |
| Data contract | семантика, версии, unknown, миграции | UI-детали без влияния на данные |
| Roadmap/backlog | порядок и состояние работы | вечные архитектурные истины |
| Project knowledge | устойчивые подтверждённые факты | пошаговый лог сессии |
| Session context | короткий актуальный checkpoint | накопительный дневник проекта |
| Audit/research | вопрос, метод, evidence, вывод и ограничения | автоматически действующее правило |
| ADR | одно значимое решение, альтернативы и последствия | каталог всех мелких правок |

## Источники истины

- Для одного вопроса выбирается один канонический документ.
- Остальные документы ссылаются на него и не копируют большие нормативные блоки.
- Устаревший статус заменяется актуальным, а не бесконечно дописывается снизу.
- Исторический audit не переписывается под текущее состояние; новое решение фиксируется в каноническом документе.
- Документация обновляется вместе с принятым изменением, не только в конце большой задачи.

## Качество текста

- Заголовок отражает назначение документа.
- Факты, решения, планы и неизвестное названы явно.
- Команды копируемы, пути актуальны, ссылки относительны внутри репозитория.
- Даты используются для snapshot и исследования, но устойчивое правило не привязывается к дате без причины.
- Не дублировать README, код, Git history или внешний provider, если достаточно ссылки.
- Пример помечается как пример и не выдаётся за обязательный default.

## Checkpoint

Перед паузой в незавершённой значимой работе сохранить:

- активную задачу и конкретный подшаг;
- что изменено и что проверено;
- точную ошибку, если есть;
- последнюю проверенную гипотезу;
- последний принятый выбор;
- одно следующее действие;
- вопросы, требующие решения.

Checkpoint должен позволить продолжить работу без восстановления контекста по памяти или чату.

## Изменение структуры

Перед удалением или перемещением документа:

1. найти входящие ссылки и навигационные карты;
2. выбрать новый источник истины;
3. обновить ссылки;
4. только затем удалить или переместить старый файл;
5. проверить локальные ссылки и diff.
