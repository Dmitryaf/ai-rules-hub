# Качество и проверка

## Матрица риска

Проверка выбирается по риску, а не по количеству изменённых строк.

| Изменение | Минимальная проверка |
| --- | --- |
| Документация | ссылки, структура, `git diff --check`, просмотр diff |
| Чистая логика | unit tests, typecheck/lint, граничные значения |
| UI | component/e2e по критическому пути, keyboard, mobile, empty/error |
| Данные или миграция | fixtures старых версий, round-trip, rollback/backup |
| API или интеграция | contract/runtime validation, expected failures, timeout/retry |
| Build/route/deploy | production build, прямые маршруты, assets, fresh и cached session |
| Security/privacy | отдельный негативный сценарий и проверка отсутствия утечки |

Локальные команды проекта имеют приоритет над примерами из хаба.

## Для каждого блока

1. Повторно прочитать изменённый код и документацию.
2. Проверить happy path, пустые, старые, ошибочные и граничные данные.
3. Добавить или обновить тест для главного правила, преобразования или миграции.
4. Проверить пользовательское подтверждение успеха и понятную ошибку.
5. Для UI проверить клавиатуру, узкую ширину, длинный текст и стабильность layout.
6. Сверить терминологию во всех затронутых поверхностях.
7. Просмотреть diff на временный код, debug output, generated files, секреты и scope creep.

## Перед передачей

- Выполнить релевантные project checks после последнего изменения.
- Выполнить `git diff --check` и `git status --short`.
- Если formatter или fix-команда меняет файлы, сначала предпочесть read-only check.
- Не удалять созданный пользователем артефакт только потому, что он мешает проверке.
- Отдельно перечислить проверки, которые нельзя было выполнить локально.

Полный check, запущенный до последнего изменения, не доказывает готовность текущего состояния.

## Критерий готовности

Изменение готово, когда:

- заявленный результат работает целиком или промежуточная граница явно согласована;
- ключевые ошибки обработаны;
- источник истины и runtime validation не нарушены;
- важный риск защищён тестом либо записанной ручной проверкой;
- документация отражает фактическое состояние;
- следующие функции не нужны для полезности текущего результата.
