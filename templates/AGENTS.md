# Правила работы агента

Всегда начинай с:

1. `.ai-rules/RULESET.md`;
2. `.ai-rules/PROJECT_RULES.md`;
3. `.ai-rules/upstream/CORE.md`;
4. всех выбранных файлов из `.ai-rules/upstream/profiles/`;
5. только относящихся к задаче файлов из `.ai-rules/upstream/rules/`;
6. релевантной проектной документации, кода и тестов.

Точный состав профилей и тем определяй через `.ai-rules/manifest.json`, `.ai-rules/lock.json` и проектный status. `.ai-rules/RULESET.md` объясняет причины выбора и явные исключения, а `.ai-rules/PROJECT_RULES.md` содержит правила именно этого проекта.

Остальные managed-правила читай только по типу задачи:

- изменение кода — `IMPLEMENTATION.md`, а при изменении границ или данных также `ARCHITECTURE_AND_DATA.md`;
- тесты и проверки — `QUALITY.md`;
- эксплуатационная надёжность, деградация, восстановление или performance/capacity — `RELIABILITY_AND_OPERATIONS.md`;
- документация — `DOCUMENTATION.md`;
- commit, ветка, PR, release или публикация — `GIT_AND_DELIVERY.md`;
- продуктовый сценарий или UI — `PRODUCT.md`;
- чувствительные данные — `SECURITY_AND_PRIVACY.md`;
- исследование или неизвестный API — `RESEARCH_AND_EVIDENCE.md`;
- создание или обновление учебной документации по проекту — `PROJECT_STUDY.md`;
- взаимодействие с AI — `AI_COLLABORATION.md`.

Читай профиль целиком, но не весь `upstream/` и не все темы профиля. Тематический файл должен одновременно входить в effective-набор и относиться к текущей задаче. `PROJECT_STUDY.md` читается только при явном выборе этой темы и задаче на учебную документацию.

Маршрут к проектной документации указан в `.ai-rules/PROJECT_RULES.md`. Если у проекта есть `docs/README.md`, используй его как индекс, но не читай всю папку `docs/` без связи с текущей задачей.

Только `.ai-rules/upstream/` управляется хабом: не редактируй его вручную. Изменение общего правила делается в хабе, проектное правило — в `.ai-rules/PROJECT_RULES.md`, а явное отступление от общего правила — в `.ai-rules/RULESET.md`.

Перед работой проверь `git status` и сохрани несвязанные изменения. Для средней или большой задачи веди короткий план с одним активным пунктом.

Выполняй релевантные проверки, перечисленные в `.ai-rules/PROJECT_RULES.md`. Не выполняй commit, push, release, публикацию, переписывание истории или удаление данных без отдельного явного разрешения владельца.
