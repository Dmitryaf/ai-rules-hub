# Правила работы агента

Всегда начинай с:

1. `RULESET.md`;
2. `PROJECT_RULES.md`;
3. `.ai-rules/rules/CORE.md`.

`RULESET.md` описывает выбранные профили, тематические правила и явные исключения. `PROJECT_RULES.md` содержит правила именно этого проекта.

Остальные managed-правила читай только по типу задачи:

- изменение кода — `IMPLEMENTATION.md`, а при изменении границ или данных также `ARCHITECTURE_AND_DATA.md`;
- тесты и проверки — `QUALITY.md`;
- документация — `DOCUMENTATION.md`;
- commit, ветка, PR, release или публикация — `GIT_AND_DELIVERY.md`;
- продуктовый сценарий или UI — `PRODUCT.md`;
- чувствительные данные — `SECURITY_AND_PRIVACY.md`;
- исследование или неизвестный API — `RESEARCH_AND_EVIDENCE.md`;
- взаимодействие с AI — `AI_COLLABORATION.md`.

Читай только файлы, которые перечислены в `RULESET.md` и существуют внутри `.ai-rules/`. Затем изучи релевантные продуктовые, архитектурные и data-документы проекта, существующую реализацию и тесты затронутого сценария.

`.ai-rules/` управляется хабом. Не редактируй файлы внутри него вручную. Изменение общего правила делается в хабе, проектное правило — в `PROJECT_RULES.md`, а явное отступление от общего правила — в `RULESET.md`.

Перед работой проверь `git status` и сохрани несвязанные изменения. Для средней или большой задачи веди короткий план с одним активным пунктом.

Выполняй релевантные проверки, перечисленные в `PROJECT_RULES.md`. Не выполняй commit, push, release, публикацию, переписывание истории или удаление данных без отдельного явного разрешения владельца.
