# Промпт завершения подключения и первичного аудита

Используйте этот запрос после `init` и первого `update -Apply`. Запускайте агента из корня подключаемого проекта. Общие правила уже находятся в `.ai-rules/upstream/`; переносить их вручную в локальные файлы не нужно.

## Готовый запрос

```text
Заверши подключение AI Rules Hub, зафиксируй границу изменений и затем проведи первичный аудит проекта.

Границы задачи:
- можно менять только корневой AGENTS.md, .ai-rules/RULESET.md и .ai-rules/PROJECT_RULES.md;
- остальные файлы кода, документацию, тесты, CI, настройки, зависимости и Git используй только для чтения;
- не выполняй commit, push, публикацию, удаление или исправление найденных разрывов;
- сохрани несвязанные изменения владельца.

Фаза 1 — подключение:
1. Проверь git status и существующие локальные инструкции.
2. Прочитай .ai-rules/manifest.json и .ai-rules/lock.json. Затем прочитай RULESET.md, PROJECT_RULES.md, CORE.md, выбранные профили и все темы итогового набора: для этого аудита они относятся к задаче.
3. Изучай проект постепенно: сначала точки входа и индексы, затем только связанные документы, конфигурацию, код и тесты. Не загружай весь репозиторий без необходимости.
4. Не копируй общие правила из upstream. Объедини маршруты с существующим AGENTS.md, в PROJECT_RULES.md оставь только фактическую специфику проекта, а в RULESET.md — причины выбора, явные исключения и подтверждённые или неизвестные разрывы.
5. Заполни оставшиеся незаполненные места только подтверждёнными данными. Если источник или проверка отсутствует, укажи «не установлен» или «не установлена». Не создавай недостающие документы, инструменты или CI.
6. Покажи изменения трёх локальных файлов и явно сообщи о завершении фазы подключения. После этого не меняй ни один файл проекта.

Фаза 2 — аудит только для чтения:
7. Проведи аудит соответствия итоговому набору правил. Для каждого значимого пункта используй один машинный статус: satisfied, gap, not applicable или unknown. Подтверждай вывод точным файлом, настройкой, командой или наблюдаемым поведением.
8. Отдельно проверь архитектурные границы и направление зависимостей, источники истины, безопасность данных и AI-инструментов, публичность документов, проверки проекта и соблюдение основного языка текста.
9. Если команда хаба доступна по известному пути, выполни doctor и status для проекта. Другие проверки запускай только без изменения исходного состояния и временных файлов.

В результате покажи:
- какие из трёх локальных файлов правил изменены в фазе подключения и зачем;
- краткую таблицу аудита, сначала риски безопасности, данных и критического поведения;
- неизвестное и чем его проверить;
- предлагаемые отдельные задачи на исправление без их выполнения.
```

Статусы в запросе оставлены точными машинными значениями, чтобы отчёты разных проектов можно было сравнивать. Сам отчёт и пояснения пишутся на основном языке проекта.
